faf-text

How it works

Every glyph on this page is a set of quadratic Bézier curves living in a GPU texture, and every pixel of every glyph decides inside-or-outside for itself, per frame, in a fragment shader. No atlas for outlines, no signed-distance bake, no MSAA. That one decision — made robust at exact edges, made fast with band tables and early-outs, made cheap to feed with a retained scene — is the renderer, and this page walks it end to end: from the bytes of a font file, through the winding rule and its failure modes, to the memory layout, the geometry around the glyphs, variable weight and color emoji, and finally 3D panes, the terminal grid, and the benchmark scorecard.

Nothing here is an artist's impression. Every figure draws the renderer's actual data, pulled through faf_text::inspect — the same flattener, band builder and clip solver that feed the GPU — and every live cell is the real renderer compiled to WebAssembly, running on WebGPU where the browser has it and on WebGL2 where it does not. Sections boot their figures as you reach them; the prose needs no GPU at all.
